## 1. 为什么需要位置编码

Transformer 的 Self-Attention 本身是**置换不变的**——它把输入当作一个"集合"来对待，不关心词的先后顺序：

- "我 爱 你" → Attention 计算和 "你 爱 我" 是一样的（如果交换位置，输出也交换，但对应关系不变）
- 但自然语言中，词序至关重要："狗咬人" vs "人咬狗"

所以必须给每个 token 的位置注入一个**位置信号**，让模型知道词的前后关系。

### 常见方案

| 方案 | 做法 | 缺点 |
|------|------|------|
| **绝对位置编码**（原始 Transformer） | 学习一个位置嵌入表，加到 token 嵌入上 | 不能外推到训练时没见过的长度 |
| **Sinusoidal 编码**（原始 Transformer 备选） | 用固定频率的 sin/cos 函数生成位置信息 | 表达能力有限 |
| **RoPE（旋转位置编码）** | 将位置信息**旋转**进 Q/K 向量中 | 相对位置感知、可外推 |

## 2. RoPE 的核心思想

### 2.1 一句话概括

> RoPE 对 Q 和 K 向量的每一对维度施加一个**随位置变化的旋转**，使得两个 token 的注意力分数只依赖于它们的**相对位置**。

### 2.2 直观类比：时钟指针

想象一个时钟：

- 时针在 **位置 0**（12 点方向）指向正上方
- 在 **位置 1**（1 点钟方向）顺时针旋转了 30°
- 在 **位置 t** 旋转了 `t × 30°`

两个指针**指向的夹角** = `|t₁ - t₂| × 30°`，这正是**相对位置**。

RoPE 做的事情完全一样：

- 每个 token 在 **位置 t**，它的 Q/K 向量会被旋转 `t × θ` 角度
- 两个 token 的 Q·K 点积中，自动包含了 `(t₁ - t₂) × θ` 的相位差

### 2.3 数学形式

对于向量中的第 `i` 对维度 `(x_{2i}, x_{2i+1})`，旋转操作是：

```
[x_{2i}']   =  [cos(t·θ_i)  -sin(t·θ_i)] [x_{2i}]
[x_{2i+1}']    [sin(t·θ_i)   cos(t·θ_i)] [x_{2i+1}]
```

其中 `θ_i = base^{-2i/dim}`，不同维度对有不同的旋转速度。

### 2.4 维度速度的"分层"设计

关键点：**不同维度旋转的速度不一样**。

| 维度 i | θ_i | 含义 |
|--------|-----|------|
| 0 | `base^0 = 1` | 旋转最快，编码相对位置细节 |
| 1 | `base^{-2/dim}` | 中等速度 |
| ... | ... | ... |
| dim/2-1 | `base^{-(dim-2)/dim}` | 旋转最慢，编码绝对位置范围 |

**为什么这样设计？**
- 高频维度（i 小 → θ 大 → 旋转快）：分辨相邻 token 的细微位置差异
- 低频维度（i 大 → θ 小 → 旋转慢）：感知长距离的 token 位置

这就好像：
- 秒针（高频，转得快）告诉你"这一秒和下一秒"
- 时针（低频，转得慢）告诉你"这是上午还是下午"

## 3. precompute_freqs_cis 逐行解析

### 3.1 函数签名

```python
def precompute_freqs_cis(dim: int, end: int = 32768, rope_base: float = 1e6, rope_scaling: dict = None):
```

- `dim`：每个注意力头的维度（head_dim），在 MiniMind 中为 96
- `end`：最大序列长度，默认 32768
- `rope_base`：旋转基数，默认 1,000,000
- `rope_scaling`：YaRN 扩展参数（稍后解释）

### 3.2 第一步：计算频率 ω_i

```python
freqs = 1.0 / (rope_base ** (torch.arange(0, dim, 2)[: (dim // 2)].float() / dim))
```

对应数学公式：`ω_i = 1 / base^{2i/dim}`，其中 `i = 0, 1, ..., dim/2 - 1`

| 步骤 | 结果 (dim=6) |
|------|-------------|
| `torch.arange(0, 6, 2)` | `[0, 2, 4]` |
| `[: (6//2)]` → `[:3]` | `[0, 2, 4]` |
| `除以 dim=6` | `[0.0, 0.333, 0.667]` |
| `base^{上一步}` (base=100) | `[1.0, 4.64, 21.5]` |
| `1/上一步` → **ω_i** | `[1.0, 0.215, 0.0465]` |

所以：
- `ω_0 = 1.0`（最快）
- `ω_1 ≈ 0.215`
- `ω_2 ≈ 0.0465`（最慢）

**物理含义**：ω_i 代表第 i 对维度的**角频率**（弧度/步长）。

### 3.3 第二步：生成所有位置的旋转角度

```python
t = torch.arange(end)  # t = [0, 1, 2, ..., end-1]
freqs = torch.outer(t, freqs)  # shape: (end, dim//2)
```

矩阵 `freqs[t, i] = t × ω_i`：

| 位置\维度 | ω_0=1.0 | ω_1=0.215 | ω_2=0.0465 |
|-----------|---------|-----------|------------|
| t=0 | 0.0 | 0.0 | 0.0 |
| t=1 | 1.0 | 0.215 | 0.0465 |
| t=2 | 2.0 | 0.430 | 0.0930 |
| t=3 | 3.0 | 0.645 | 0.1395 |
| ... | ... | ... | ... |

### 3.4 第三步：生成 cos 和 sin 矩阵

```python
freqs_cos = torch.cat([torch.cos(freqs), torch.cos(freqs)], dim=-1)  # (end, dim)
freqs_sin = torch.cat([torch.sin(freqs), torch.sin(freqs)], dim=-1)  # (end, dim)
```

为什么复制一份拼接起来？

因为在上面的旋转公式中，维度 `i` 与维度 `i + dim/2` 配对。看 [apply_rotary_pos_emb](#4-apply_rotary_pos_emb-逐行解析) 中的 `rotate_half`：

```python
def rotate_half(x):
    return torch.cat((-x[..., x.shape[-1] // 2:], x[..., : x.shape[-1] // 2]), dim=-1)
```

对于 dim=6 的向量 `[x₀, x₁, x₂, x₃, x₄, x₅]`：
- 前半 `[x₀, x₁, x₂]`
- 后半 `[x₃, x₄, x₅]`
- `rotate_half` = `[-x₃, -x₄, -x₅, x₀, x₁, x₂]`

**配对关系**：维度 0↔3, 1↔4, 2↔5（即 `i ↔ i+dim/2`），所以 cos/sin 数组需要复制一份，使维度 i 和 i+dim/2 使用相同的 ω_i。

| 维度索引 | 0 | 1 | 2 | 3 | 4 | 5 |
|---------|---|---|---|---|---|---|
| cos 来源 | ω₀ | ω₁ | ω₂ | ω₀（复制） | ω₁（复制） | ω₂（复制） |
| sin 来源 | ω₀ | ω₁ | ω₂ | ω₀（复制） | ω₁（复制） | ω₂（复制） |
| 配对 | ←→ 维度3 | ←→ 维度4 | ←→ 维度5 | ←→ 维度0 | ←→ 维度1 | ←→ 维度2 |

### 3.5 输出

```python
return freqs_cos, freqs_sin  # shape: (end, dim), (end, dim)
```

预计算了所有位置（0 到 end-1）的 cos 和 sin 值，推理时直接查表，无需重复计算。

## 4. apply_rotary_pos_emb 逐行解析

### 4.1 函数签名

```python
def apply_rotary_pos_emb(q, k, cos, sin, unsqueeze_dim=1):
```

对 Q 和 K 向量施加旋转位置编码。

### 4.2 旋转逻辑

```python
def rotate_half(x):
    return torch.cat((-x[..., x.shape[-1] // 2:], x[..., : x.shape[-1] // 2]), dim=-1)

q_embed = (q * cos.unsqueeze(unsqueeze_dim)) + (rotate_half(q) * sin.unsqueeze(unsqueeze_dim))
k_embed = (k * cos.unsqueeze(unsqueeze_dim)) + (rotate_half(k) * sin.unsqueeze(unsqueeze_dim))
```

将向量 `q` 分解为两个部分 `q_A = q[..., :d/2]` 和 `q_B = q[..., d/2:]`：

| 项 | 公式 | 前半部分 (0 ~ d/2-1) | 后半部分 (d/2 ~ d-1) |
|----|------|---------------------|---------------------|
| q · cos | q × cos(tθ) | q_A × cos(tθ_A) | q_B × cos(tθ_B) |
| rotate_half(q) · sin | rotate_half(q) × sin(tθ) | (-q_B) × sin(tθ_A) | q_A × sin(tθ_B) |
| **q_embed** | 两项相加 | q_A·cos - q_B·sin | q_B·cos + q_A·sin |

这正是**旋转矩阵**作用于向量对 `(q_A, q_B)` 的结果：

```
q_embed_A = q_A × cos(tθ) - q_B × sin(tθ)   ← 旋转公式
q_embed_B = q_B × cos(tθ) + q_A × sin(tθ)   ← 旋转公式
```

> 注意：这里的配对是 `(维度 i, 维度 i+d/2)`，而不是标准 RoPE 论文中的 `(维度 2i, 维度 2i+1)`。两者数学上等价，只是维度排列不同。

### 4.3 为什么 Q 和 K 都要旋转？

因为注意力分数是 Q·K^T，当 Q 和 K **都旋转相同角度**时，点积结果反映的是**相对位置差**：

```
Q(t₁) · K(t₂) = R(t₁)q · R(t₂)k = q·R(t₁)ᵀR(t₂)k = q·R(t₂ - t₁)k
```

> 注意 `R(t₁)ᵀR(t₂) = R(t₂-t₁)`，因为旋转矩阵是正交的，且旋转可叠加。

所以点积只依赖于 `t₂ - t₁`（相对位置），这正是我们想要的性质。

## 5. 完整数值例子

### 5.1 设置

```
dim = 4，rope_base = 100，位置 t = 2
查询向量 q = [1.0, 2.0, 3.0, 4.0]（为方便演示，用标量值）
```

### 5.2 precompute_freqs_cis 计算

**步骤 1：计算 ω**

```python
arange(0, 4, 2) = [0, 2]
[: (4//2)] = [:2] = [0, 2]
除以 dim： [0/4, 2/4] = [0.0, 0.5]
base^指数： [100^0.0, 100^0.5] = [1.0, 10.0]  
ω = 1/上一步： [1.0, 0.1]
```

因此：
- `ω₀ = 1.0`（高频，转得快）
- `ω₁ = 0.1`（低频，转得慢）

**步骤 2：位置 t=2 的角度**

```
角度₀ = t × ω₀ = 2 × 1.0 = 2.0 弧度
角度₁ = t × ω₁ = 2 × 0.1 = 0.2 弧度
```

**步骤 3：生成 cos/sin**

```
cos(角度₀) = cos(2.0) ≈ -0.416
cos(角度₁) = cos(0.2) ≈ 0.980

sin(角度₀) = sin(2.0) ≈ 0.909
sin(角度₁) = sin(0.2) ≈ 0.199
```

复制拼接：

```
cos = [cos(ω₀t), cos(ω₁t), cos(ω₀t), cos(ω₁t)]
    = [-0.416, 0.980, -0.416, 0.980]

sin = [sin(ω₀t), sin(ω₁t), sin(ω₀t), sin(ω₁t)]
    = [0.909, 0.199, 0.909, 0.199]
```

### 5.3 apply_rotary_pos_emb 计算

**步骤 1：q × cos**

```
q × cos = [1.0 × (-0.416), 2.0 × 0.980, 3.0 × (-0.416), 4.0 × 0.980]
        = [-0.416, 1.960, -1.248, 3.920]
```

**步骤 2：rotate_half(q)**

```
q = [1.0, 2.0, 3.0, 4.0]
前半 = [1.0, 2.0]，后半 = [3.0, 4.0]
rotate_half(q) = [-3.0, -4.0, 1.0, 2.0]
```

**步骤 3：rotate_half(q) × sin**

```
rotate_half(q) × sin = [-3.0×0.909, -4.0×0.199, 1.0×0.909, 2.0×0.199]
                     = [-2.727, -0.796, 0.909, 0.398]
```

**步骤 4：相加得到 q_embed**

```
q_embed = q×cos + rotate_half(q)×sin
        = [-0.416+(-2.727), 1.960+(-0.796), -1.248+0.909, 3.920+0.398]
        = [-3.143, 1.164, -0.339, 4.318]
```

旋转后的 q 从 `[1.0, 2.0, 3.0, 4.0]` 变成了 `[-3.143, 1.164, -0.339, 4.318]`，所有维度的值都根据位置 t=2 进行了旋转。

### 5.4 相对位置验证

现在验证不同位置的 Q 和 K 点积是否只依赖于相对位置。

假设我们有两个 token：
- 位置 2 的 Q、K 都用上面的参数旋转
- 位置 5 的 Q、K 也用同样的方法旋转（只是角度变大）

**Q(位置2) · K(位置5)** 的数学结果中，角度部分会出现 `(5-2)×ω = 3×ω`，即只依赖于相对位置 3。

这样，无论绝对位置是 (2,5) 还是 (10,13)，Q·K 的结果都相同——这正是 RoPE 的优美之处。

## 6. YaRN 扩展（进阶）

### 6.1 为什么要扩展？

当推理长度远超训练长度时，RoPE 会遇到"**位置溢出**"问题：

- 训练时最大 2048 个 token，ω_i 只在 `[0, 2047]` 范围内有意义
- 推理时突然要处理 8192 个 token，位置角度的取值范围变大
- 高频维度（ω 大）会旋转很多圈，模型没见过这种"疯狂旋转"的情况

### 6.2 YaRN 的思路

对每个频率 ω_i 进行**个性化缩放**：

```
ω_i' = ω_i × (1 - γ_i + γ_i / s)
```

其中：
- `s` = 缩放因子（如 16）
- `γ_i` = 线性斜坡，从 0（高频维度）到 1（低频维度）

**高频维度（i 小，ω 大）**：γ ≈ 0 → ω_i' ≈ ω_i（几乎不变，保持局部精度）
**低频维度（i 大，ω 小）**：γ ≈ 1 → ω_i' ≈ ω_i / s（压缩频率，避免旋转过多）

### 6.3 代码对应

```python
inv_dim = lambda b: (dim * math.log(orig_max / (b * 2 * math.pi))) / (2 * math.log(rope_base))
low = max(math.floor(inv_dim(beta_fast)), 0)   # 高频边界
high = min(math.ceil(inv_dim(beta_slow)), dim // 2 - 1)  # 低频边界
ramp = torch.clamp((index - low) / (high - low), 0, 1)   # 线性斜坡
freqs = freqs * ((1 - ramp) + ramp / factor)  # 对中间维度渐变缩放
```

| beta_fast=32 | beta_slow=1 | 含义 |
|-------------|------------|------|
| 小于 low 的维度 | 高频，不缩放 | 保持局部位置精度 |
| low ~ high 之间 | 过渡带，逐渐缩放 | 平滑过渡 |
| 大于 high 的维度 | 低频，完全缩放 | 适应长序列 |

## 7. 总结

### 7.1 数据流

```
precompute_freqs_cis                    apply_rotary_pos_emb
                                        
dim, base, max_len                      q[bsz, seq, n_head, head_dim]
        |                               cos[end, head_dim], sin[end, head_dim]
        v                                       |
  计算 ω_i = 1/base^{2i/dim}                    |
        |                                       v
        v                               取对应位置的 cos(t), sin(t)
  生成全位置角度 t × ω_i                         |
        |                                       v
        v                               旋转公式：
  生成 cos/sin 矩阵 (end, dim)          q_embed = q·cos(t) + rotate_half(q)·sin(t)
        |                                       |
        v                                       v
  存储为 buffer, 推理时查表              Q/K 带上位置信息进入 Attention
```

### 7.2 关键点回顾

| 概念 | 说明 |
|------|------|
| **ω_i** | 第 i 维对的角频率，随 i 增大而减小 |
| **t × ω_i** | 位置 t 在维度 i 上的旋转角度 |
| **配对** | 维度 i 与 i+dim/2 配对，用同一 ω_i 旋转 |
| **cos/sin 拼接** | 复制一份使配对维度获得相同频率 |
| **相对位置** | Q·K 点积只依赖位置差，因旋转可叠加 |
| **YaRN** | 高频不变、低频压缩，扩展模型支持的长度 |

### 7.3 与模型整体的关系

在 MiniMind 中，RoPE 的使用流程是：

```
1. 模型初始化时 → precompute_freqs_cis 生成 cos/sin 矩阵（model.py:219）
2. 每个 forward 调用时 → 切片取出当前序列位置的 cos/sin（model.py:233）
3. Attention 层中 → apply_rotary_pos_emb 旋转 Q 和 K（model.py:133）
4. 旋转后的 Q/K → 参与 Attention 分数计算
```
